# BOK_regression

한국은행 기준금리 변동과 국내 산업별 성장률의 관계를 분기 시계열 회귀분석으로 살펴보는 프로젝트입니다. 금리 **인상**과 **인하**를 별도 설명변수로 구성해 산업마다 추정계수가 어떻게 달라지는지 비교하고, 결과를 표와 그래프로 출력합니다.

> **분석의 성격:** 통화정책과 산업 성장률 사이의 **통계적 연관성**을 탐색합니다. 추정계수만으로 기준금리 변화의 인과효과가 입증되는 것은 아닙니다.

## 분석 개요

- **종속변수:** 산업별 부가가치 성장률(제공된 전처리 파일의 로그차분 계열)
- **핵심 설명변수:** 기준금리 인상분(`rate_up_w`), 인하분(`rate_dn_w`)
- **거시 통제변수:** GDP 성장률, 환율 변화, 소비자물가(CPI), 경제심리지수(ESI)
- **기타 통제:** 산업별 성장률의 과거값(AR 항), 2020Q1~2020Q4 코로나19 더미
- **추정:** OLS 회귀 + Newey–West HAC 표준오차(`maxlags=4`)
- **진단:** 결정계수(R²·수정 R²), Durbin–Watson 통계량, VIF 및 회귀 잔차 시각화

금리 인상분과 인하분은 원래 금리 변화의 양·음 방향을 나누어 **각각 0 이상의 크기**로 저장합니다. 코드에서 표시하는 산업별 *순 민감도*는 **`β(인상) − β(인하)`**입니다. 이는 이 프로젝트의 비교 지표이며, 독립적으로 검증된 정책 충격의 인과효과나 통계적 유의성 검정 결과를 의미하지 않습니다.

### 분석 대상 산업

| 그룹 | 산업 |
| --- | --- |
| 1차·건설 | 농림어업, 건설업 |
| 제조업 | 제조업 전체, IT 제조업, 비IT 제조업 |
| 서비스업 | 서비스업 전체, 금융 및 보험업, 부동산업, 도소매·숙박·음식업 |

총 **9개 산업 계열**을 코드에서 정의합니다. 실제 추정에 포함되는 산업과 관측치 수는 입력 파일의 결측치 및 열 이름에 따라 달라집니다.

## 코드 구성

| 파일 | 역할 |
| --- | --- |
| [`growth.py`](growth.py) | 산업별로 미리 지정한 설명변수·AR 항을 사용하여 OLS/HAC 추정 및 시각화 |
| [`최적알고리즘.py`](최적알고리즘.py) | 거시변수별 **0~4분기 후보 시차**를 탐색하고 산업별 회귀모형을 추정 |
| `기준금리.xlsx` | 기준금리 변화 계열 |
| `GDP.xlsx` | GDP 계열 |
| `환율.xlsx` | 환율 계열 |
| `cpi.xlsx` | 소비자물가 계열 |
| `경제심리지수.xlsx` | 경제심리지수 계열 |
| `건설업.xlsx`, `농림어업.xlsx`, `제조업.xlsx` | 산업별 성장률 계열 |
| `서비스업.xlsx` | 서비스업 하위 산업 계열. **확장자는 .xlsx이지만 코드에서는 CP949 인코딩 CSV로 읽음** |
| [`LICENSE`](LICENSE) | 소스코드의 MIT 라이선스 |

`최적알고리즘.py`는 일반 거시변수의 후보 시차별 회귀에서 **p-value 최소**(동률 시 R² 최대)를 기준으로 선택하며, 금리 인상·인하에는 같은 시차를 적용합니다. 이는 **표본 내 탐색 절차**로, 예측 성능이 검증된 자동 모델 선택이나 인과적 최적 시차 추정을 뜻하지 않습니다.

## 실행 환경

- Python **3.10 이상 권장**(`dict | None`, `list[str]` 형태의 타입 표기 사용)
- 주요 패키지: `pandas`, `numpy`, `statsmodels`, `matplotlib`, `openpyxl`
- 그래프의 한글 표시에는 맑은 고딕 또는 나눔고딕 등의 한글 폰트 권장

```bash
git clone https://github.com/y-willy/BOK_regression.git
cd BOK_regression
python -m pip install pandas numpy statsmodels matplotlib openpyxl
```

### 경로 설정 (자동)

**사용자 PC의 절대경로를 수정할 필요가 없습니다.** 두 스크립트는 실행한 터미널의 현재 위치가 아니라 **파이썬 파일이 저장된 폴더**(`__file__`)를 기준으로 입력 자료를 읽습니다. 저장소에 포함된 Excel/CSV 파일을 스크립트와 같은 폴더에 두세요.

```text
BOK_regression/
├── growth.py
├── 최적알고리즘.py
├── GDP.xlsx, 기준금리.xlsx, 환율.xlsx, cpi.xlsx, ...
└── outputs/                # 실행할 때 자동 생성
    ├── growth/             # growth.py 그래프
    └── optimized/          # 최적알고리즘.py 그래프
```

- 입력: `os.path.join(os.path.dirname(os.path.abspath(__file__)), "파일명.xlsx")` 형태로 자동 해석합니다.
- 출력: 두 스크립트의 결과 폴더를 구분해 동일한 그래프 이름으로 서로 덮어쓰지 않습니다.
- 입력 파일명·열 이름은 코드가 기대하는 이름과 일치해야 합니다. 특히 `서비스업.xlsx`는 파일명과 달리 **CP949 CSV** 형식이므로 이름만 변경하거나 Excel로 읽도록 바꾸지 마세요.
- Windows의 맑은 고딕/나눔고딕 및 Linux 나눔고딕 경로는 **선택적 시스템 폰트 탐색용**이며 입력 데이터나 결과의 저장 위치가 아닙니다. 해당 글꼴이 없으면 기본 글꼴로 대체되어 한글 표시가 깨질 수 있습니다.

### 실행

```bash
# 고정 변수·시차 구성
python growth.py

# 변수별 시차(0~4분기) 탐색
python "최적알고리즘.py"
```

명령을 실행하면 산업별 회귀계수, 표준오차, p-value, R², Durbin–Watson, VIF, 민감도 순위가 **터미널에 출력**됩니다. 그래프 파일은 각각 `outputs/growth/`, `outputs/optimized/`에 저장됩니다. 각 실행 폴더 내부에서는 같은 이름의 기존 결과 파일이 다시 생성될 때 덮어써질 수 있습니다.

- `산업별_금리민감도_비교.png` — 산업별 인상·인하 계수 차이 및 신뢰구간 표시

- `산업별_실질충격_히트맵.png` — 거시변수의 1표준편차 변동을 이용한 상대적 비교

**주의:** 민감도 막대그래프의 신뢰구간 계산은 두 금리계수의 공분산을 반영하지 않는 근사식입니다. 따라서 계수 차이의 정확한 95% 신뢰구간이나 유의성 검정으로 인용하려면 회귀계수 공분산행렬을 이용한 별도 검증이 필요합니다.

## 재현성과 해석 시 주의사항

1. **고정 모형의 시차 표기 불일치:** `growth.py`의 `rate_up_w_lag2` 및 `rate_dn_w_lag2` 열은 이름과 달리 실제 코드에서 `shift(1)`로 생성됩니다. 따라서 현재 출력에 표시되는 “t-2”를 검증 없이 **실제 2분기 지연 효과**로 해석하면 안 됩니다. 반면 `최적알고리즘.py`는 `shift(lag)`를 이용해 0~4분기 시차를 생성합니다.
2. **단위 확인 필요:** 금리 변수에 `×25`, 로그차분 변수에 `×100`을 적용합니다. 원본 Excel의 단위와 해당 변환이 일치하는지 확인한 후 계수 크기를 해석해야 합니다.
3. **결측치 처리:** 분기별 병합과 시차 생성 후 `dropna()`를 실행하므로 실제 추정 표본은 원본 데이터 전체와 다를 수 있습니다.
4. **ESI 누락:** ESI 자료 로딩에 실패하면 코드가 경고를 출력하고 ESI 값을 0으로 대체할 수 있습니다. 이러한 실행의 결과는 정상적인 ESI 관측자료를 사용한 분석과 구별해야 합니다.
5. **시차 탐색의 과적합 가능성:** `최적알고리즘.py`의 p-value 중심 시차 선택은 동일 표본 내 반복 탐색입니다. 다중검정·선택 편향 가능성을 고려해야 하며, 별도 표본 외 검증을 수행하지 않습니다.
6. **인과해석 제한:** 자기상관·이분산에 대한 HAC 표준오차는 추정 불확실성에 대한 보정이며, 정책 내생성이나 누락변수 편향을 자동으로 해결하지 않습니다.
7. **데이터 출처:** 저장소에는 분석용 가공 파일이 포함되어 있지만 각 파일의 **원본 통계 출처·다운로드 시점·원자료 이용조건**을 코드만으로 완전히 확정할 수 없습니다. 외부 공개·보고서 인용 전 각 원자료의 메타데이터와 이용조건을 별도로 확인해야 합니다.
